# گزارش فاز ۲ — پایهٔ مهندسی و کنترل کیفیت

**وضعیت:** تکمیل‌شده؛ آمادهٔ ورود به فاز ۳ پس از تأیید مالک محصول

## خروجی‌های اجراشده

در این فاز ابتدا runtime لازم برای توسعه و آزمون فراهم شد: PHP 8.3.6، Composer 2.7.1 و افزونه‌های `pdo_mysql`, `mbstring`, `xml`, `zip` و `gd`. وابستگی‌های قفل‌شدهٔ پروژه با Composer نصب شدند. در زمان شروع، نبود GD باعث شکست نصب PhpSpreadsheet شد؛ افزونه نصب و همان عملیات با موفقیت تکرار شد.

برای آماده‌سازی ساختار ماژولار، PSR-4 در Composer افزوده شد و namespaceهای `App\` و `Tests\` به‌ترتیب به `app/` و `tests/` متصل شدند. ابزارهای typed پایه شامل `TrackingCode`, `Clock` و `SystemClock` ایجاد شدند تا گزارش خطا/پشتیبانی شناسهٔ همبسته داشته باشد و منطق زمان/تقویم در فازهای بعد قابل آزمون باقی بماند. تست‌های واحد برای قالب کد پیگیری و منطقهٔ زمانی افزوده شد.

در بازبینی خط پایه، PHPStan یک خطا در `install.php` گزارش کرد: فایل runtime `db_config.php` در تحلیل استاتیک وجود نداشت. به‌جای سرکوب خطا، installer اصلاح شد تا نبود فایل تنظیمات را به‌صورت کنترل‌شده، با پیام فارسی، مدیریت کند و در صورت وجود آن به‌صورت absolute path آن را بارگذاری نماید. این اصلاح یک نقص واقعی را نیز برطرف می‌کند: ارسال مستقیم کاربر به مرحلهٔ دوم بدون تکمیل مرحلهٔ اتصال اکنون به خطای کنترل‌شده می‌رسد.

## فایل‌های تغییرکرده یا افزوده‌شده

| مسیر | نوع تغییر |
|---|---|
| `composer.json` | PSR-4 autoload و autoload-dev |
| `composer.lock` | بدون تغییر وابستگی؛ مطابق lock موجود نصب شد |
| `install.php` | guard امن برای نبود `db_config.php` |
| `app/Support/TrackingCode.php` | utility نوع‌دار برای tracking code |
| `app/Support/Clock.php` | قرارداد زمان قابل تزریق |
| `app/Support/SystemClock.php` | پیاده‌سازی ساعت سیستم |
| `tests/Unit/Support/SupportUtilitiesTest.php` | دو تست واحد پایه |
| `docs/` | SRS، ماتریس مجوز، مدل داده، Backlog، پذیرش، گزارش فاز ۰ و همین گزارش |

## نتایج کنترل کیفیت

| کنترل | نتیجه |
|---|---|
| PHPUnit | سبز: ۷ تست و ۱۶ assertion |
| PHP syntax lint | سبز: تمام فایل‌های PHP بررسی‌شده بدون خطای syntax |
| PHPStan | سبز: ۴۶ فایل تحلیل‌شده و بدون خطا |
| Composer autoload | سبز: `App\Support\TrackingCode` از vendor autoload بارگذاری شد |
| git diff --check | سبز: خطای whitespace مشاهده نشد |
| تست Installer | `php -l install.php` سبز؛ اجرای کامل MySQL در این مرحله به محیط دیتابیس نیاز دارد |

## موارد خارج از ادعای این گزارش

فاز ۲ هنوز installer SaaS، tenancy واقعی، احراز هویت چندنقشی، پروندهٔ بیمار و جدول‌های جدید دندان را پیاده‌سازی نکرده است؛ این‌ها طبق Backlog در فازهای ۳ تا ۶ اجرا می‌شوند. سبز بودن تست‌های این گزارش فقط به معنی سالم‌بودن پایهٔ فعلی و ابزارهای افزوده‌شده است و نباید به‌عنوان تکمیل MVP تلقی شود.

## دروازهٔ ورود به فاز ۳

برای آغاز فاز ۳، تأیید مالک محصول لازم است. پس از تأیید، ابتدا Migrationهای هستهٔ SaaS، `clinic_id`/tenant context، وضعیت‌های کلینیک و installer جدید طراحی و با تست‌های جداسازی دو کلینیک پیاده‌سازی خواهند شد. در پایان فاز ۳، همین تست‌های پایه به‌علاوهٔ سناریوهای نصب، tenant isolation، login، session و RBAC اجرا و گزارش می‌شوند.
