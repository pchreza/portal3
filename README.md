# سیستم هوشمند پورتال مشتریان (فاز اول و دوم)

این پروژه یک پورتال هوشمند مشتریان حرفه‌ای و بهینه شده است که به صورت اختصاصی با **PHP خالص** و پایگاه داده **MySQL (PDO)** طراحی و پیاده‌سازی شده است. هیچ فریم‌ورک سنگینی (مانند لاراول) در این سیستم استفاده نشده تا نصب، راه‌اندازی و انتقال آن بر روی هر هاست یا سروری بسیار ساده و سریع باشد.

---

## قابلیت‌های فاز اول و فاز دوم:

1. **طراحی حرفه‌ای UI/UX با فونت وزیرمتن (Vazirmatn)**:
   - پشتیبانی کامل از زبان فارسی و راست‌چین (RTL).
   - استایل‌دهی مدرن با Tailwind CSS buildشده به‌صورت local، با ظاهر کاربرپسند و واکنش‌گرا (Responsive).

2. **ویزارد نصب ساده (`install.php`)**:
   - بررسی خودکار اتصال به پایگاه داده و ساخت جدول‌های موردنیاز (`settings`, `users`, `projects`, `products`, `tickets`, `ticket_messages`, `invoices`).
   - فرم تعیین اطلاعات حساب کاربری ادمین در مرحله نصب.

3. **پنل مدیریت (Admin Panel)**:
   - **داشبورد**: آمار کلی تعداد مشتریان، پروژه‌ها، محصولات، تیکت‌ها و فاکتورها.
   - **مدیریت مشتریان**: تعریف دستی مشتریان با فیلدهای کامل (نام، نام خانوادگی، موبایل، شرکت، سمت، تاریخ تولد، جنسیت).
   - **مدیریت پروژه‌ها و محصولات**: تعریف و انتصاب به مشتریان.
   - **تنظیمات فیلدهای اجباری**: انتخاب فیلدهای اجباری برای پروفایل مشتریان.
   - **مدیریت فاکتورها (`invoices.php`)**: صدور، ویرایش و مدیریت صورتحساب‌های مالی مشتریان.
   - **مدیریت تیکت‌ها (`tickets.php`)**: پاسخ به تیکت‌های پشتیبانی مشتریان و تغییر وضعیت تیکت.

4. **پنل مشتریان و پنل پشتیبانی (Customer Panel)**:
   - **داشبورد اختصاصی**: نمایش پروژه‌ها و محصولات منتسب شده.
   - **تکمیل پروفایل با دکمه «رد کردن»**: مدیریت فیلدهای اجباری تعیین شده توسط ادمین.
   - **فاکتورهای من (`invoices.php`)**: مشاهده صورتحساب‌ها و وضعیت پرداخت.
   - **تیکت‌های پشتیبانی (`tickets.php`)**: ارسال تیکت جدید و مکاتبه دوطرفه با پشتیبانی.

---

## راهنمای نصب و راه‌اندازی:

1. فایل‌های پروژه را بر روی هاست PHP (یا محیط لوکال مانند XAMPP / MAMP) آپلود کنید.
2. مرورگر خود را باز کرده و به آدرس نصب پروژه بروید (مثلا `http://localhost/client-portal/install.php`).
3. اطلاعات اتصال به دیتابیس MySQL خود را وارد کرده و روی دکمه «مرحله بعد و تست اتصال» کلیک کنید.
4. در مرحله دوم، نام کاربری و رمز عبور حساب ادمین را وارد کرده و نصب را تکمیل کنید.
5. پس از اتمام نصب، به صفحه اصلی (`index.php`) منتقل شده و با حساب ادمین وارد سیستم شوید.

### نصب وابستگی‌های اکسل (PhpSpreadsheet):

برای خروجی/ورود فایل‌های اکسل (مشتریان، محصولات، پروژه‌ها و تیکت‌ها)، کتابخانه `phpoffice/phpspreadsheet` لازم است:

1. `composer install` را در ریشه پروژه اجرا کنید (نیازمند PHP CLI و [Composer](https://getcomposer.org)).
2. در صورت نبودن این کتابخانه، سیستم خودکار به نسخه ساده داخلی برمی‌گردد (با محدودیت سازگاری).

> در release نصب، پوشهٔ `vendor/` عمداً قرار نمی‌گیرد. در ریشهٔ پروژه `composer install --no-dev` را اجرا کنید؛ برای توسعه از `composer install` استفاده کنید.

## ساختار پروژه (بازسازی‌شده):

پروژه به صورت **PHP خالص** باقی مانده اما کدهای تکراری قالب (HTML Head، سایدبار، نوار بالا و پاصفحه)
در قالب‌های مشترک (`includes/layout/`) یکپارچه شده‌اند و توابع کمکی بر اساس حوزه‌ی کاری
در `includes/functions/` دسته‌بندی شده‌اند:
```
portal3/
├── config.php                      ← بوت‌استرپ: سشن، اتصال PDO، بارگذاری توابع
├── index.php                       ← صفحه ورود (قالب عمومی)
├── install.php                     ← ویزارد نصب
├── migrations.php                  ← مهاجرت‌های نسخه‌بندی‌شده
├── schema.sql                      ← اسکیمای دیتابیس
├── admin/                          ← پنل مدیریت (هر صفحه فقط منطق + محتوای خود را دارد)
│   ├── auth.php                    ← احراز هویت مدیر
│   ├── sidebar.php
│   └── *.php
├── customer/                       ← پنل مشتری (همان الگو)
│   ├── auth.php
│   ├── sidebar.php
│   └── *.php
└── includes/
    ├── functions/                  ← توابع کمکی دسته‌بندی‌شده
    │   ├── helpers.php             ← e()، redirect()، CSRF، رندر قالب‌ها
    │   ├── auth.php                ← قفل تلاش ورود
    │   ├── settings.php            ← get_setting / set_setting / is_module_enabled
    │   ├── custom_fields.php       ← فیلدهای سفارشی پویا
    │   ├── surveys.php             ← توابع ماژول نظرسنجی
    │   └── activity.php            ← ثبت لاگ فعالیت‌ها
    └── layout/                     ← قالب‌های مشترک
        ├── admin_header.php / admin_footer.php
        ├── customer_header.php / customer_footer.php
        └── public_header.php / public_footer.php
```

### نحوه استفاده از قالب مشترک در یک صفحه:

```php
<?php
require_once 'auth.php';
// ... منطق صفحه ...

render_admin_header('عنوان صفحه');          // یا render_customer_header()
?>
<!-- محتوای اصلی صفحه -->
<?php render_admin_footer();
```

### امضای توابع رندر:

- `render_admin_header($title, $mainClass, $extraStyles, $topbarActions)`
- `render_customer_header($title, $mainClass, $extraStyles, $topbarActions, $topbarUser)`
- `render_public_header($title, $bodyClass, $extraStyles)`

مزایا: حذف ~۵۵۰ خط کد تکراری، یکپارچگی ظاهری، تغییر سراسری استایل‌ها در یک نقطه،
و خوانایی بهتر صفحات (مخصوصاً صفحات نظرسنجی که قبلاً تک‌خطی بودند).

## ارتقای نسخه (مهاجرت‌های نسخه‌بندی‌شده):

این پروژه از **مهاجرت‌های نسخه‌بندی‌شده** (`migrations.php`) استفاده می‌کند. در production، migrationها خارج از request وب و با command صریح اجرا می‌شوند تا اولین کاربر باعث تغییر schema نشود.

### انتشار نسخهٔ جدید:

1. پیش از ارتقا از دیتابیس backup بگیرید و امکان restore را بررسی کنید.
2. فایل‌های نسخهٔ جدید را جایگزین کنید.
3. وابستگی‌ها را با `composer install --no-dev --prefer-dist --optimize-autoloader` نصب کنید.
4. migration را با `php bin/migrate.php` اجرا کنید.
5. سپس health check و smoke test را اجرا کنید. اگر migration عقب باشد، برنامهٔ production به‌جای اجرای خودکار، پاسخ maintenance کنترل‌شده می‌دهد.

برای local/test می‌توان `PORTAL_AUTO_MIGRATE=true` را فعال کرد؛ این گزینه برای production توصیه نمی‌شود. هنگام افزودن migration، `PORTAL_SCHEMA_VERSION` را با آخرین شماره هماهنگ و آزمون rollback/دادهٔ ناسالم را مستند کنید.

## دیت پیکر شمسی (Jalali DatePicker):

همه فیلدهای تاریخ در سیستم (تاریخ تولد مشتری، تاریخ خرید محصول، ددلاین پروژه، سررسید فاکتور)
به یک **تقویم شمسی** مجهز هستند:

- کتابخانه: [JalaliDatePicker](https://github.com/majidh1/JalaliDatePicker) (لایسنس MIT، بدون وابستگی)
- فایل‌ها به‌صورت محلی در `assets/jalalidatepicker/` نگهداری می‌شوند؛ بدون نیاز به CDN.
- هر `input` که ویژگی `data-jdp` داشته باشد خودکار به تقویم شمسی تبدیل می‌شود.
- محدودیت‌های منطقی:
  - تاریخ تولد و تاریخ خرید: حداکثر «امروز» (`data-jdp-max-date="today"`)
  - ددلاین پروژه و سررسید فاکتور: حداقل «امروز» (`data-jdp-min-date="today"`)
- خروجی تقویم با جداکننده `/` و اعداد انگلیسی است (سازگار با داده‌های قبلی)، مثلا `1404/06/15`.

### افزودن دیت پیکر به یک فیلد تاریخ جدید:

```html
<input type="text" name="my_date" data-jdp data-jdp-min-date="today">
```

### نسخه پشتیبان (Backup):

- آخرین بکاپ: `/home/user/portal2_backup` (اسکریپت بازگشت: `bash restore_backup.sh`)
- بکاپ‌های نسخه‌دار: `/home/user/portal2_backups/`


## تنظیمات امن production

متغیرهای محیطی نمونه در `.env.example` آمده‌اند و این فایل به‌صورت خودکار توسط PHP بارگذاری نمی‌شود. آن‌ها را در سرویس وب و jobهای CLI تنظیم کنید. `PORTAL_DEV_MODE` در production باید `false` بماند، `PORTAL_AUTO_MIGRATE` باید خاموش باشد و migration فقط با `php bin/migrate.php` اجرا شود. اگر برنامه پشت reverse proxy است، فقط در همان محیط `PORTAL_TRUST_PROXY=true` را فعال کنید؛ در غیر این صورت برنامه به هدرهای forwarded اعتماد نمی‌کند.

کلید سرویس پیامک دیگر در جدول settings ذخیره نمی‌شود و باید فقط در `PORTAL_SMS_API_KEY` قرار گیرد. مقدار کلید را هرگز در repository، ZIP release، screenshot یا log وارد نکنید. برای assetهای CSS، فایل local با `pnpm install` و `pnpm run build:css` بازتولید می‌شود؛ `node_modules/` در release قرار نمی‌گیرد.
